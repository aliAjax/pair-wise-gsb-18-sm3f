# hxwl-04 牙科根管治疗长期记录看板

把纸质根管治疗卡数字化为按牙位长期跟踪的看板：复诊时可立即查到牙位、各根管工作长度与治疗进度。

## 业务规则

- **步骤推进**：同一牙位固定按 开髓 → 测长 → 根管预备 → 冲洗 → 封药 → 充填 推进，只能操作当前步骤。
- **测长闸门**：任一根管未填工作长度，不能提交/进入根管预备（按钮与卡片均有 🔒 提示）。
- **可补录字段**：主尖锉号（#）与下次复诊日期在未充填前可随时补录/修改，并写入操作记录。
- **双角色确认**：助理录入检查数据并提交，医生确认后步骤才算完成；医生可驳回并注明原因，助理修改后重新提交。
- **逾期置顶**：复诊日期早于当前日期的未充填病例自动排在看板最前并标红，显示逾期天数。
- **充填锁定**：充填经医生确认后病历锁定，全部记录保留可查，但任何字段不可改。
- **筛选**：看板支持 待复诊 / 封药 / 工作长度 三个筛选，外加牙位、患者、诊断搜索。
- **持久化**：全部数据保存在浏览器 localStorage，关闭页面后重新打开完整恢复。

## 内置示例

首次打开提供 5 份演示病历：#36 封药逾期（置顶）、#11 已充填锁定、#46 测长待医生确认、#25 开髓后未测长、#47 封药待复诊。右上角可切换 助理 / 医生 身份体验流程。

## 技术栈

React 19 + Vite + TypeScript（严格模式）+ 原生 CSS，数据存储 localStorage。

## 本地运行

```bash
npm install
npm run dev       # 开发，端口 5104
npx tsc --noEmit  # 单独做严格类型检查
npm run build     # 打包
npm run preview   # 预览构建产物
```

## 目录

```
src/
  types.ts            数据模型（病历、根管、步骤、操作记录）
  domain.ts           步骤规则、测长闸门、逾期判定、筛选与排序
  storage.ts          localStorage 持久化、示例数据、新建病历
  stepConfig.ts       六个步骤的结构化录入字段
  App.tsx             看板：指标、筛选、列表、角色切换
  components/
    CaseCard.tsx      看板病例卡（进度条、逾期/封药/待确认标记）
    CaseDetail.tsx    病历详情：步骤表单、根管表、复诊、操作记录
    NewCaseModal.tsx  新建病历（FDI 牙位 + 常见根管解剖预置）
```
